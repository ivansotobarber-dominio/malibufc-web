# Hoja de ruta del ecosistema digital Malibú FC

Fecha de revisión: 2026-07-29.

Este documento establece la secuencia de evolución y los criterios de salida. Las tareas concretas se mantienen exclusivamente en `docs/BACKLOG.md`.

## Estado actual

La fase 0 está en curso. Existe una web estática revisada y `malibufc.es` está confirmado, pero la web no está publicada. Continúan bloqueados datos, contactos, catálogo, contenidos legales e indexación; la delegación DNS y GitHub Pages tampoco están activos.

## Fase 0. Fundaciones

Objetivo: convertir el repositorio en una fuente de verdad comprensible y segura.

Resultado: gobierno documental, estructura mínima útil, Git y GitHub configurados, ausencia de secretos y primera publicación controlada.

Criterio de salida: una nueva sesión puede entender el proyecto sin consultar conversaciones externas, la documentación no se contradice y el repositorio remoto es operativo.

## Fase 1. Web pública mínima

Objetivo: publicar una presencia oficial sencilla, responsive y verificable.

Resultado: portada, información confirmada del club y equipos, catálogo preparado, patrocinadores, contacto, Instagram, proceso de pedido y páginas legales.

Criterio de salida: la web funciona en móvil y ordenador, utiliza dominio propio y HTTPS, y permite iniciar solicitudes por WhatsApp sin presentar placeholders como hechos.

## Fase 2. Catálogo y venta manual

Objetivo: ordenar la venta de productos sin incorporar costes fijos.

Resultado: modelo de producto, catálogo mantenible, flujo WhatsApp y Bizum, y registro privado del estado de cada pedido.

Criterio de salida: el club puede publicar productos, recibir solicitudes, confirmar pagos y controlar entregas sin exponer datos personales ni utilizar una tienda de pago.

## Fase 3. Gestión deportiva básica

Objetivo: facilitar la gestión del primer y segundo equipo.

Resultado: modelos y procesos de plantilla, renovaciones, disponibilidad, asistencia, convocatorias y partidos en una herramienta adecuada a su privacidad.

Criterio de salida: los responsables pueden conocer disponibilidad, preparar convocatorias y mantener el histórico de ambos equipos con permisos apropiados.

## Fase 4. Comunicación y contenidos

Objetivo: profesionalizar la comunicación manteniendo el tono del club.

Resultado: calendario editorial, flujo de aprobación, archivo de contenidos y plantillas reutilizables para Instagram, WhatsApp y comunicados.

Criterio de salida: cada publicación tiene objetivo, responsable, activos, fecha, estado y resultado trazables.

## Fase 5. Identidad visual y activos

Objetivo: centralizar y gobernar los materiales oficiales.

Resultado: escudo, variantes, colores, tipografías, equipaciones, fotografías, plantillas y criterios de uso documentados.

Criterio de salida: los activos oficiales tienen versión, procedencia, autorización y reglas de aplicación claras.

## Fase 6. Patrocinadores

Objetivo: profesionalizar la relación comercial y el cumplimiento de compromisos.

Resultado: inventario de patrocinadores, aportaciones, contraprestaciones, vigencia, activos, publicaciones, renovaciones y documentación.

Criterio de salida: el club puede conocer compromisos, evidencias de visibilidad y próximos hitos de cada patrocinador.

## Fase 7. Automatización y profesionalización

Objetivo: automatizar únicamente procesos cuyo volumen justifique el coste y mantenimiento.

Resultado potencial: formularios privados, convocatorias automáticas, base de datos, administración, stock, tarjeta, área privada, socios, estadísticas, calendario, newsletter, redes, analítica y almacenamiento profesional.

Criterio de entrada: problema recurrente medido, responsable asignado, alternativa manual insuficiente y evaluación favorable de coste, complejidad, privacidad, mantenimiento y portabilidad.

Criterio de salida: la solución implantada alcanza un indicador de éxito definido sin introducir una dependencia desproporcionada.

## Reglas de transición

Una fase puede iniciar trabajos preparatorios antes del cierre total de la anterior cuando no dependa de información bloqueada y aporte valor autónomo. No se activará ninguna capacidad pública o sensible sin responsable, datos confirmados y revisión de privacidad.

El avance de fase se registrará en `docs/DECISIONS.md`. El estado de ejecución se actualizará en `docs/BACKLOG.md`.
